Failure census preview — 567-labs/instructor

Generated 2026-10-15 from 7 public issues. This is page one of a failure census: the dominant agent-failure classes in this project's own tracker, each with the deterministic check that would catch it.

The dominant pattern across this page of issues is silence: parsers, mergers, and stream handlers encounter data or config they don't recognize and drop it instead of failing loudly, while request builders overwrite caller-supplied settings without surfacing the conflict. None of these are provider API bugs — they are instructor's own internal normalization and dispatch layers losing information between input and output.

silent-data-corruption

Parsing and schema-generation code paths quietly drop, mangle, or misclassify data instead of raising an error, so bad or incomplete results pass through undetected.

Evidence: “Unknown tool names should raise a clear parsing” — #2696 #2756 #2526 #2613

The deterministic check: Assert that every field/key/tool_call present in the raw input is present (or explicitly accounted for) in the parsed output; fail the parse with a typed error if the input and output key/name sets don't match exactly.

tool-config-override

Provider request builders overwrite or ignore caller-supplied configuration (tools, auth parameters) instead of merging with it, silently disabling features the caller explicitly requested.

Evidence: “explicitly ignores the `api_key` argument and only wires up classic credential parameters” — #2713 #2408

The deterministic check: Before sending the provider request, diff the caller-supplied config against the finally-sent payload; fail the build if any caller-supplied key (tools, api_key, tool_choice) was dropped or replaced without an explicit override flag.

streaming-event-drop

The streaming/partial-parsing layer only forwards a hardcoded subset of provider event types, so unrecognized event types (like reasoning summaries) vanish with no error or fallback.

Evidence: “These events are silently dropped and never surfaced to the caller.” — #2291

The deterministic check: Add an exhaustive match/else branch over the provider's documented streaming event union; raise or log on any event type not in the explicit handled set instead of falling through silently.
