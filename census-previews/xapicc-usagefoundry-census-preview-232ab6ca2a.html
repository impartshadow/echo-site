Failure census preview — Xapicc/UsageFoundry

Generated 2026-08-19 from 11 public issues. This is page one of a failure census: the dominant agent-failure classes in this project's own tracker, each with the deterministic check that would catch it.

Across this tracker the dominant pattern is that the system trusts its own state without checking it: config values, doc claims, build status, and scale assumptions are all taken on faith rather than verified, and failures surface silently (no error, no log, no CI) until an external sweep or audit stumbles onto them. The fix in every cluster is the same shape — an explicit boundary check or gate that runs before the silent-failure path is reachable.

silent-config-failure

Config values that are blank, missing, or over a hard-coded limit are accepted without any error, warning, or log line, so the system silently drifts from what the operator configured — a missing repo mount or a relocated database looks like normal operation.

Evidence: “silently relocates the entire database out of the persistent volume” — #77 #98

The deterministic check: Boot-time assertion that rejects (not defaults) any required env var that is empty, unset, unwritable, or exceeds a declared slot count, and refuses to start rather than falling back.

doc-reality-drift

Documentation and UI copy assert behavior — defaults, limits, causal claims — that the code and tests directly contradict, and the gap was never checked before being written down.

Evidence: “which appends the run's own last turn marked as its account” — #142 #119 #56

The deterministic check: CI step that greps docs for numeric/behavioral claims (defaults, limits, 'unlimited', 'never') and diffs them against the corresponding source constants or a runtime assertion.

unverified-push

Changes and claims of correctness ship without anyone actually running the verification commands — the build has been broken and undetected long enough that four independent audits hit it separately.

Evidence: “nothing runs typecheck, tests or the build” — #112 #57

The deterministic check: CI pipeline that runs typecheck, test, and build on every push/PR and blocks merge on nonzero exit, closing the exact gap this issue documents.

scale-readiness-blocker

Core isolation assumptions (per-run uid, credential scoping, spend guards, backup path) that hold at small scale silently stop holding once concurrency and repo count increase, and nothing in the code enforces the limits the deployment depends on.

Evidence: “Fourteen findings were marked blocker across four domains” — #114 #110 #89 #78

The deterministic check: Load/chaos test at the target concurrency (25 runs, 15 repos) asserting uid isolation, per-run cost caps, and credential scoping hold, gating deploy on that test passing.
