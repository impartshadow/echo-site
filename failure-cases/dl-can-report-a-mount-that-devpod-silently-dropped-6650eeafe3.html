Observed agent action

dl prints a mount-success notice based on the --mount argv it sends to devpod, before devpod up has run and before the resulting container is inspected.

Expected boundary

A success notice about container state should only be emitted after verifying that state against the live container, not before the operation that produces it has completed.

Runtime context

Compose devcontainer workspaces where devpod caches multiple generated docker-compose override files per workspace and selects one via the container's com.docker.compose.project.config_files label, independent of which override contains the requested mount.

Evidence supplied

Across eight measured compose workspaces, seven up runs requesting the same mount produced two successful binds and five silent drops, and deleting the cached override files before rerunning fixed all five.
