Generated 2026-08-21 from 8 public issues. This is page one of a failure census: the dominant agent-failure classes in this project's own tracker, each with the deterministic check that would catch it.

Across these eight issues the dominant pattern is silence: failures, drops, and wrong data all resolve to a 200/success/no-error state instead of an observable failure, spanning build tooling (2030), API mutations (2017, 1987), content ingestion (2024, 1880), request construction (1951), transport (1957), and environment isolation (1898). None of these are logic bugs in the traditional sense — they are missing boundary checks between 'the call was accepted' and 'the call did what was claimed,' which is exactly the class of defect that survives code review and only surfaces when a user notices stale content, a missing tool, or a leaked email.

silent-success-reporting

An operation partially or fully fails, but the caller only sees the enqueue/HTTP 200 or a per-attachment warning bucket, so the UI or CI reports success while the real work never happened.

Evidence: “does nothing for any file that is already chunked, and reports success anyway” — #2017 #1987 #2030

The deterministic check: Assert response/exit status is derived from item-level outcome, not from enqueue acceptance: reprocess mutation must fail/no-op-flag when the idempotency guard skips chunking; importTools must surface llmParams validation throws in `errors`, not silently into `attachmentWarnings`; bundler entrypoint must set process.exitCode=1 whenever errorCount>0 before help:build is considered green.

silent-parameter-and-content-drop

A request is built or content is transformed without carrying forward a required field (selected model, HTML-to-text extraction, structured message content), so the backend silently receives the wrong value and produces wrong output with no error.

Evidence: “silently ignores whichever Gemini model the user selected and always runs the edit against” — #1951 #2024 #1880

The deterministic check: Contract test comparing outbound payload against the user-facing selection/source: assert GeminiImageService.edit() receives `model` equal to the session's selected model; assert stored fab-file text matches an extracted-text fixture (no raw tags, headings/lists/tables preserved) rather than raw HTML or `<p>`-only text; assert Anthropic system content is text-joined, never `JSON.stringify`'d or bare `.join()`'d, for array-valued content blocks.

silent-transport-data-loss

The WebSocket fanout protocol changed to chunk large payloads, but the client never implemented reassembly, so any push over 120KB is dropped with no error and the UI silently stops updating.

Evidence: “the frame is silently dropped and the document update never lands” — #1957

The deterministic check: Client-side test: feed a `{_chunked:true,_chunkIndex,_totalChunks,_data}` sequence into WebsocketContext's onMessage and assert the reassembled message is dispatched to the matching `action` listener, not routed to the fallback `setLastJsonMessage` path.

partial-stage-isolation-fix

A stage-aware routing fix was applied to one delivery channel (Slack) but not its sibling (email), leaving non-production environments able to send to production-configured recipient lists while telemetry reports it as a normal delivery.

Evidence: “mails that same list, prod or not” — #1898

The deterministic check: Integration test asserting the email channel checks `stageClass === 'production'` (mirroring the Slack `SlackNonProdFeedbackWebhookUrl` pattern) before sending to `FeedbackReceiveEmail`, and that a nonprod-stage test run yields either a suppressed send or a dedicated nonprod recipient, not delivery to the production list.
