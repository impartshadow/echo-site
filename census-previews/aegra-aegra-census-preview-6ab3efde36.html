Failure census preview — aegra/aegra

Generated 2026-09-12 from 10 public issues. This is page one of a failure census: the dominant agent-failure classes in this project's own tracker, each with the deterministic check that would catch it.

Aegra's dominant failure mode is silent partial compliance: it accepts requests matching the LangGraph SDK/Agent Protocol surface, returns 200, but quietly drops or ignores the semantically important part (filters, durability, interrupts, projections, retries) rather than failing loudly. The interrupt-handling and auth-filter clusters show this recurring even after prior fixes, because each streaming path or route reimplements the same logic independently instead of sharing one enforced contract.

silent-field-drop

Aegra accepts request fields the LangGraph SDK sends (metadata filters, durability, if_not_exists, stream_resumable, select projections) but silently ignores them instead of rejecting or honoring them, so callers get a 200 response with wrong or incomplete results.

Evidence: “does not declare them and currently accepts the request while silently dropping them” — #582 #503 #564 #490

The deterministic check: Reject unknown/unhandled request fields with a 4xx (fail-closed schema validation) instead of allowing Pydantic to discard them; add contract tests asserting every documented SDK field either maps to behavior or raises.

auth-filter-not-enforced

Authorization handler filters that scope which threads/assistants/crons a user can see are computed but never actually applied to the underlying query on several routes, letting users read or delete data they shouldn't.

Evidence: “the filter dict itself is never merged into the underlying query” — #485 #490

The deterministic check: Integration test per resource route asserting a handler-returned filter (e.g. owner-scoped) actually narrows/blocks cross-user access on GET/DELETE by-id and search endpoints, not just list endpoints.

interrupt-config-laundering

Run-level interrupt_before/interrupt_after are stuffed into an untyped config dict that LangGraph doesn't read as config, so interrupts are silently dropped on one or more streaming code paths even after being 'fixed' once.

Evidence: “config keys by that name, it only accepts them as explicit kwargs” — #482 #481 #442

The deterministic check: Unit test per streaming producer (v1 graph_streaming, v2 native_stream) asserting interrupt_before/after are passed as explicit astream/astream_events kwargs, not left in the config dict — run against every producer, not just the one touched by the latest patch.

durability-not-wired

The durability/checkpoint-frequency setting is documented and requested by clients but never actually passed into graph execution, so every run gets full per-step checkpointing regardless of what was configured.

Evidence: “never passes `durability` to `graph.astream()` / `graph.astream_events()`” — #500 #503

The deterministic check: Assert graph.astream/astream_events calls always receive an explicit durability kwarg derived from the request/server default, with a test that fails if the call site omits it.

no-retry-transient-failure

The Redis SSE broker's write path has no retry on transient Redis errors, so momentary network blips silently drop stream events even though Redis itself is healthy.

Evidence: “the write path (`RedisRunBroker.put`) has **no retry**, while the read path does” — #439

The deterministic check: Require symmetric retry/backoff policy on all Redis broker read and write paths, verified by a test that injects a single transient RedisError and asserts the event is still delivered, not dropped.
