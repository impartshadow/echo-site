Failure census preview — langchain-ai/langgraph

Generated 2026-10-04 from 7 public issues. This is page one of a failure census: the dominant agent-failure classes in this project's own tracker, each with the deterministic check that would catch it.

The highest-severity cluster is silent state loss under concurrency or failure: parent-graph Command fan-outs and crash-time run state both get dropped or corrupted without any error surfaced to the caller. A second cluster covers data-integrity edges in the Command/error primitives themselves (unpicklable state, exception identity) that only appear under specific serialization or resume paths. The remaining cluster is lower-severity documentation and test-harness gaps where configuration is accepted but silently ignored or inflexible rather than validated.

parent-graph-command-handling

When tools return Command objects targeting the parent graph, especially with fan-out via Send, the runner silently drops one tool's update/goto instead of merging or erroring, and which one survives is nondeterministic.

Evidence: “are dropped without an error, and which one survives changes from run to run.” — #9072

The deterministic check: Assert that the number of ParentCommand updates emitted by the Pregel runner for a single supersteps equals the number of sibling tool calls that returned Command(graph=PARENT, ...); fail loudly if any are discarded instead of merged.

command-serialization-safety

Command objects can carry live resources like locks or connections in their update field, and calling repr/print on them crashes or forces an expensive deepcopy instead of failing gracefully.

Evidence: “In stateful workflows, node updates or resume values may hold resources” — #9175

The deterministic check: Unit test that Command.__repr__ on a state dict containing an unpicklable object (e.g. threading.Lock) returns a bounded, non-crashing string without invoking asdict()/deepcopy on the full object graph.

error-identity-loss-on-resume

After a node raises and the graph is resumed, the original exception type/instance passed to the error handler and surfaced via get_state() gets degraded into a plain string, losing type information needed for recovery logic.

Evidence: “get a str instead of the exception after resume” — #9085

The deterministic check: Regression test asserting isinstance(error.error, ValueError) still holds (not a str) when the error handler is invoked after a checkpointed resume, matching behavior on first run.

runtime-state-leak-on-restart

The in-memory runtime never resets runs that were left 'running' by a killed process and never implements the TTL sweep, so restarts accumulate permanently wedged threads and unbounded memory until the process is OOM-killed.

Evidence: “by a dead process survive restart and permanently wedge their thread” — #9078

The deterministic check: Startup integration test: kill the process mid-run, restart, and assert the run's status is reconciled away from 'running' and that Threads.sweep_ttl actually deletes entries older than checkpointer.ttl.

docs-and-test-config-gaps

Documentation and test suites don't account for real-world deployment variance — model-provider string resolution for OpenAI-compatible gateways, config keys that are silently ignored outside their expected scope, and hardcoded localhost assumptions in checkpoint tests.

Evidence: “passes `max_concurrency` inside `configurable`, where it is silently ignored” — #8957 #8920 #9050

The deterministic check: Add a config-schema validation step that raises on unrecognized keys inside `configurable` (e.g. max_concurrency) instead of silently ignoring them, and parameterize Redis test fixtures on REDIS_HOST/REDIS_PORT env vars instead of hardcoding localhost.
