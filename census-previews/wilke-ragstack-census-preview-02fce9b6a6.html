Failure census preview — wilke/ragstack

Generated 2026-08-06 from 7 public issues. This is page one of a failure census: the dominant agent-failure classes in this project's own tracker, each with the deterministic check that would catch it.

The dominant pattern is processes that lie about their own completeness: ingest jobs exit 0 or report 'completed' while silently dropping or overwriting data (#176, #260, #134), and a separate but related fragility lets one poison record abort an entire bulk operation instead of being contained (#175). A third, architectural pattern shows the collection/library model being repeatedly re-patched for isolation, aliasing, and multi-collection querying rather than designed for it up front (#230, #179, #253).

unverified-push (silent-success-on-partial-failure)

Ingest processes report success and exit 0 even when they dropped data or deleted records they never replaced — the exit code and checkpoint are not evidence of a complete run, they just reflect that no exception surfaced.

Evidence: “A task that raises a non-transient error is never observed.” — #176 #260 #134

The deterministic check: Before returning exit 0 or status=completed, assert every submitted async task was reaped and its exception explicitly consumed, and that the checkpoint's contiguous-frontier count equals the stats-reported chunk/doc count; any mismatch forces a non-zero exit instead of a clean one.

unbounded-input-abort

A single malformed input record (an oversized field, a fully-quarantined document) is allowed to abort or corrupt an entire bulk operation instead of being isolated to just that record.

Evidence: “a single bad source row kills a whole corpus ingest” — #175

The deterministic check: Enforce a max-length/ignore_above bound on every keyword-mapped field at schema-definition time, with a test asserting one oversized field value degrades only that field/doc rather than raising document_parsing_exception and aborting the bulk request.

collection-abstraction-leak

The collection/library naming and query model keeps needing ad-hoc patches — physical-name collisions, missing alias support, singular-only queries — because the abstraction wasn't built for multi-tenant, multi-collection use from the start.

Evidence: “Content uploaded to one appeared in all; a delete would have hit all three.” — #230 #179 #253

The deterministic check: Require a test that creates two libraries with an identical (model, dim, chunk_descriptor) build-spec and asserts they resolve to physically isolated stores/aliases, plus schema validation that rejects unresolved access or over-cap collection fan-out at request time rather than on first-leg failure.
