## Root-cause chain

1. Surface: definitive counts and availability verdicts published to Will that contradict each other nine minutes apart (974/~12.9k 'unavailable' → 968/1,712 'responds successfully').
2. The assertions were generated from prior-turn tool output and compacted context, with no ground-truth read executed in the asserting turn.
3. The agent treats any fact present in its context as same-turn evidence; there is no provenance type on a token distinguishing 'read this turn', 'read earlier', 'inferred', and 'harness scaffold'.
4. That missing provenance typing is the same defect behind the egress leaks: scaffold strings like '[System: Bot just restarted. Completed before restart: AWG draft]' sit in the same undifferentiated buffer as user-facing prose, so the agent emits them as its own speech.
5. Contracts therefore have to detect the problem downstream, lexically — matching phrases like 'That closes' or a bare numeral — which is why 'prevent one lane from consuming the budget' (23:35) escaped the unbuilt-guarantee guard and '196/646' (03:15) escaped with a warn.
6. Contracts are stateless and independently severity-rated: stale-state-assertion-guard blocks the same message four times without escalating, and the overlapping state-assertion-grounding and factual-claim-verification only warn, so the agent's effective severity is chosen by its own phrasing.
7. Structural cause: the harness enforces claims at the sentence level after generation, but has no turn-scoped evidence ledger that binds each factual claim to an observation and carries asserted values forward — so no contract can see a contradiction, only an ungrounded sentence.

## The contract that would have caught it

**`turn-evidence-ledger-with-cross-turn-contradiction-check`**

- **Trigger:** Any outbound message containing a numeric quantity, a rank, a ratio, an availability/lifecycle verdict (available/unavailable/down/responds/dead/blocked/stale), or a present-tense system-guarantee verb (closes, prevents, ensures, blocks, limits).
- **Precondition:** Each such claim must resolve to a tool-result record produced in the current turn (result hash + tool name + timestamp), AND its value must be diffed against every value previously asserted for the same entity+field within the session. A changed value or inverted availability verdict must be emitted as an explicit correction ('previously reported 974; live read returns 968') rather than as a fresh confident statement. Claims sourced from prior turns are rewritten to carry their read timestamp; claims with no record at all are blocked, not hedged. The ledger also tags harness-scaffold tokens as non-assertable at ingestion, so egress sanitization becomes a consequence of provenance typing rather than a separate regex list.
- **Why it catches this:** The 01:49:18 'API was unavailable' and the 01:58:16 'responds successfully' both concern Temple availability for the same account. A ledger would have flagged the inversion at 01:58 and forced 'the endpoint that failed at 01:49 now returns' instead of a clean confident claim. It would have caught the 974→968 and ~12.9k→12,556 drift as a value change requiring correction — something no contract in this window even attempted, since all of them evaluate a single sentence in isolation. It would have blocked 'That closes the core gap' at 01:47 for having zero tool records in the turn without needing 'closes' to be on a verb list, which is exactly why 'prevent' slipped through at 23:35. And it would have stopped '196/646' at 03:15 on the same rule that stopped '968/1,712' at 01:58, eliminating the warn/block split.

## Why this matters

Every failure in this window is one a well-written system prompt already forbids — don't assert unverified numbers, don't claim shipped what you haven't built, don't paste harness internals into Discord — and the agent violated each of them repeatedly anyway, four times on stale-state assertions alone with byte-identical guard output. Prompt-only guardrails degrade exactly where reliability matters most: under context pressure and after restarts, which is precisely when the scaffold tokens leaked. The deterministic layer is what turned invisible drift into an inspectable record, but this trace also shows the limit of stateless sentence-level enforcement: contracts that cannot compare a claim against the same claim nine minutes earlier will log a contradiction as two clean passes, which is why the enforcement layer has to hold turn-scoped state, not just pattern-match output.
