Resolution — fixed upstream in v2.9.0

Reticle shipped the fix in v2.9.0 (commit 2eaefd04, 2026-08-20) and closed #370. The confirmed root cause differs from this advisory's initial guess: check/uncheck was not writing the DOM property without events — it already activated through a real click. The defects were that CHECK/UNCHECK were missing from the CLICK_LIKE action set (dropping point geometry, occlusion hit-testing, and the component/source attribution — the missing-attribution tell this advisory flagged as the clearest evidence), that cancellation was read from a window listener a handler's stopPropagation() silently escaped, and that the already-matching no-op branch reported unqualified success. uncheck on a radio is now refused as a state no user can reach. What this advisory got right: the attribution gap was a second code path, not flakiness, and the checkbox and radio reports were not one root cause. What it got wrong: the direct-property-write hypothesis.
