Failure census preview — agkomyint/pentoolgg

Generated 2026-10-20 from 11 public issues. This is page one of a failure census: the dominant agent-failure classes in this project's own tracker, each with the deterministic check that would catch it.

The dominant pattern across this page of issues is Pentool's CLI/Studio layer accepting invalid or unsupported input and reporting success (exit 0, ok:true, 'healthy') instead of validating and failing loudly. This shows up as ignored flags, no-op edits reported as successful, inconsistent enforcement of the same rule across different code paths, and exporters/importers that quietly drop data. All four clusters are variations of one root cause: validation and state-change checks are implemented per-command rather than through a shared, consistently-applied contract.

silent-flag-ignore

CLI flags meant to filter or redirect output (--page, --preview-out, --cell) are accepted syntactically but silently ignored, so the command exits 0 and produces output as if the flag were never passed, with no warning that the request wasn't honored.

Evidence: “is accepted but silently ignored: the image is written” — #219 #205 #164 #180

The deterministic check: For every filtering/output-path flag (--page, --preview-out, --cell), validate the argument against the same allowed-value set used by sibling commands and fail with [invalid-input]/[missing-resource] before performing the read/write, rather than falling back to a default silently.

false-success-reporting

Health-check and edit commands return ok:true (or success exit codes) even when the underlying state is broken, unchanged, or references a nonexistent target, giving agents no signal that nothing actually happened or that the configuration is unhealthy.

Evidence: “library doctor reports healthy when an enabled library path is missing” — #233 #154

The deterministic check: Before returning ok:true, diff pre/post document state or confirm every referenced path/resource resolves; if no state changed or a referenced path/primitive is missing, return a warning/error field instead of a bare success.

cross-surface-validation-inconsistency

The same constraint (actor identity, migration target cap, page/kind filtering) is enforced on one code path but not on another equivalent one, so identical-looking commands behave differently depending on document state, version, or whether they went through the CLI vs. the API.

Evidence: “plain documents silently accept --actor-kind agent without --actor-id” — #221 #217 #151

The deterministic check: Extract each validation rule (actor-id required for actor-kind agent; migration target range; --page/--kind enum) into one shared contract function called from every entry point (CLI command, HTTP API handler, every document version branch) so no path can diverge from the others.

silent-data-loss-in-import-export

Import and export pipelines drop geometry, table content, or material overrides during format conversion without flagging the loss anywhere in their success output, leaving users to discover missing data only by manually diffing source and result.

Evidence: “PDF text extraction contains only the surrounding paragraph” — #249 #155

The deterministic check: After export/import, programmatically re-extract the output and assert every placed resource (table, normal, UV set, smoothing group, material override) present in the source document is represented in the result; if not, fail the call or populate an 'unsupported'/'dropped' report field instead of reporting success.
