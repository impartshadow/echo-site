## Root-cause chain

1. Surface: scaffold artifacts ('[Channel: #shadow-hq]', '[System: Bot just restarted...]') repeatedly stripped from outbound Discord messages, including one message that was entirely scaffold.
2. The harness injects channel headers and restart-status banners inline into the agent's prompt with no delimiter the model reliably treats as non-content, so the model reproduces and even paraphrases them in output.
3. The bot is in a crash-restart loop: the same four-message block recurs identically ~6 times, each restart re-injecting the banner and replaying the same outbound sends.
4. The egress guard's contract is sanitize-and-forward with no recurrence threshold, so it launders the loop's output on every cycle instead of halting it — deterministic enforcement without escalation becomes symptom suppression.
5. Structural cause: contracts guard individual sinks (egress text, price claims, citations) but no contract observes cross-event patterns — repeated identical violations, blocked-then-retried-without-remediation (FM-026 at 03:17:29→03:17:47), or restart frequency — so loops are invisible to the system that exists to catch loops.

## The contract that would have caught it

**`identical-violation-circuit-breaker`**

- **Trigger:** The same contract fires on a payload whose content hash matches a prior violation within a rolling window (e.g. 3 identical hits / 24h), or any block-severity contract fires twice in the same session without the prescribed remediation tool call in between.
- **Precondition:** Every contract violation event records a normalized hash of the original payload and the remediation action named in its recovery path.
- **Why it catches this:** The scaffold-leak cycle would have tripped on its second identical repetition — halting sends and paging the operator about the restart loop instead of silently sanitizing ~24 events. The FM-026 pair would have hard-stopped the 03:17:47 retry because no mcp__shadow__web_search call occurred between the two blocks, converting the contract's advice into an enforced ordering.

## Why this matters

Every leak in this window was caught deterministically — regex token matching stopped scaffold text from reaching #shadow-hq roughly two dozen times, something a prompt instruction ('never mention system banners') demonstrably fails at, since the model here paraphrased the banner into natural prose. But the trace also shows the limit of per-event enforcement: sanitize-and-forward with no memory turned a crash-restart loop into invisible steady-state noise, and a block that prescribes remediation without enforcing it was retried 18 seconds later unchanged. The lesson for buyers is that contracts must be stateful and escalating, not just deterministic — the value isn't only blocking the bad output, it's converting repeated blocks into a halt signal that no amount of prompt engineering can provide.
