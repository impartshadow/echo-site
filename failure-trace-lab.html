## Root-cause chain

1. Discord #shadow-hq receives messages that contained channel headers, restart banners, and internal task names ('AWG email draft') before sanitization.
2. The agent generates scaffold tokens in four distinct surface forms — leading bracketed, inline bracketed, unbracketed prefix, and full-message — meaning it has learned scaffold as vocabulary rather than reproducing a fixed string.
3. The egress guard fires at the sink, rewrites the payload, and returns success; the agent never sees a rejection, so nothing in its loop updates and the identical cycle replays four times unchanged.
4. The guard is therefore an output filter mislabeled as a contract: enforcement that repairs is not enforcement that corrects. Blocking-with-feedback would have collapsed this to one event.
5. The guard's rule surface is a matched_tokens list — a denylist of observed spellings — with no rule covering the degenerate case where sanitization empties the message, so the worst variant is the least handled.
6. Every one of these events is filed as FM-005, a taxonomy entry describing an unrelated failure that explicitly has no code guard, so the trace produces no signal that any owner is accountable for scaffold egress.
7. In parallel, the provenance carveout applies on domain match alone while recording hedge and fetch_tools as inert telemetry, and accepts non-MCP tool names that FM-004 classes as violations.
8. Structural cause: contracts in this harness are configured as post-hoc observers keyed on surface features — token spellings, domain labels — rather than as preconditioned gates over the fields they already collect. They can describe a violation in full detail and still be architecturally incapable of preventing its recurrence.

## The contract that would have caught it

**`scaffold-egress-blocking-gate`**

- **Trigger:** Any outbound message to an external sink (discord:*, telegram:*, email) whose draft body matches a scaffold pattern, OR whose post-sanitization body is empty or differs from the draft by more than a whitespace normalization.
- **Precondition:** sanitized == original AND len(sanitized.strip()) > 0. On failure: reject the send, return the matched_tokens and the empty/diff reason to the agent as a tool error, require a regenerated message, and increment a per-session recurrence counter that escalates to a hard halt on the third trip — with the event filed under a dedicated failure mode, not FM-005.
- **Why it catches this:** All 24 events are one cycle replayed four times, which is only possible because the guard returned success. A gate that failed the send instead of repairing it would have surfaced the leak on event 1 and blocked cycle 2 from ever being generated — cutting the trace from 24 events to roughly 7. It also closes the one case the current guard has no answer for: the messages that sanitize to "", where repair-in-place produces an empty post the agent still believes it sent.

## Why this matters

A prompt-only guardrail would have told this agent 'never emit scaffold tokens'; the trace shows it emitting them in four distinct surface forms, including paraphrases it invented — instruction-following does not generalize over rephrasing. But the deterministic guard here only half-solved it: because it sanitizes and returns success, it produced a perfect forensic record of a violation it re-enabled four times, and the parallel carveout bug shows the same shape — hedge and fetch_tools captured as fields, never evaluated as preconditions. The lesson a buyer should take is not 'deterministic beats prompting' but the sharper version: determinism only buys you enforcement when the contract is a precondition that fails closed and returns the failure to the agent. A contract that logs, repairs, and reports success is an observability feature wearing a safety label, and this trace is what its output looks like — highly detailed, perfectly correct, and four cycles deep in the same unfixed leak.
