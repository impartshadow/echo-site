Observed agent action

InMemorySaver's get_delta_channel_history walked the checkpoint ancestor chain and returned only the pre-migration value after the first post-migration write, even though the live invoke() call had correctly returned the merged result.

Expected boundary

The first write on a thread immediately after migrating a channel to DeltaChannel should be durably persisted and returned by get_state() identically to what invoke() returned, regardless of where the next snapshot boundary falls.

Runtime context

A LangGraph thread checkpointed with InMemorySaver is migrated mid-conversation from a BinaryOperatorAggregate-backed channel to a DeltaChannel-backed channel, with the default snapshot_frequency of 1000 meaning the first post-migration write is a non-snapshotting checkpoint.

Evidence supplied

get_state(config) on the new graph returned ['a'] instead of the expected ['a', 'b'] right after new_graph.invoke({'items': ['b']}, config) had itself returned the correct merged value.
