Failure census preview — SiderealPress/Lobster

Generated 2026-08-04 from 12 public issues. This is page one of a failure census: the dominant agent-failure classes in this project's own tracker, each with the deterministic check that would catch it.

The dominant pattern across Lobster's issue tracker is failures that ship silently: hallucinated completions, misconfigured hook matchers, and unverified references all pass without any error signal, and the fixes are consistently reactive post-incident diagnosis rather than pre-merge checks. A second pattern is critical-path fragility — auth, notification, and routing failures fail closed with no alerting, turning single-point failures into multi-hour outages before a user notices.

capability-denial / fabricated-completion (FM-001 family)

The dispatcher claims work was completed or a tool exists when neither is true, misleading users into believing something was delivered.

Evidence: “already uploaded both graphics to the project” — #2117

The deterministic check: Before asserting any artifact was created/uploaded, require a same-turn tool-call receipt (file path, URL, or API response ID) that proves the artifact exists; block completion claims lacking this citation.

hook-matcher-misconfiguration (event-routing failure)

Hook matcher strings and field checks are silently wrong (exact-match instead of regex, wrong field name), causing hooks to never fire without any error.

Evidence: “it has fired in only ~37% of compaction events observed since April 17” — #1947 #1985 #1984

The deterministic check: Add a unit test that feeds each hook's real-world event payload (from CC docs/logs) through the registered matcher and field-check logic, asserting a match; run this test against every hook matcher in settings.json before merge.

silent-failure / no-alerting on critical path

Auth, message-routing, and notification failures fail closed and silently, so outages and dropped messages go unnoticed for long periods.

Evidence: “This repeated on every ~2h04m restart cycle (SESSION_AGE_LIMIT proactive restart) for the full 32 hours” — #2141 #2070 #2133

The deterministic check: Any code path that exits/returns early on a failure condition (auth failure, missing reply_to_message_id, unmatched outbox source) must emit an alert to a monitored channel distinct from the failing channel itself, verified by a test that simulates the failure and asserts an alert fires.

unverified-external-reference (FM-002 family)

Generated content (URLs, schema calls, doc examples) looks structurally plausible but is never checked against the real target, so it fails or misleads downstream.

Evidence: “delivered 12 citations on 19th-century American law journals” — #2102 #2139

The deterministic check: Require an explicit fetch-and-match verification step for every generated external reference (URL fetch confirming document identity, or a schema validation call against the live tool) before it is included in output or documentation.

dead-code / superseded-artifact accumulation

Old hooks, scripts, and integrations are replaced but never removed, leaving stale code and docs that can confuse future installs or maintenance.

Evidence: “The old file was never deleted.” — #1987 #1998

The deterministic check: CI check that greps install.sh/settings.json for hook filenames not present in hooks/, failing the build if a registered or referenced file no longer exists or has a known successor.
